# 주간 보고 초안 (대시보드 표준 섹션)

> 실험실 기능이다. 형식과 절차는 바뀔 수 있다.

대시보드 주간 보고 탭의 AI 브리핑은 초안 md에서 정해진 이름의 섹션을 찾아 배치한다. 이 스킬은 그 형식 그대로 초안을 쓴다.

- **형식 원본**: 이 스킬 폴더에서 두 단계 위의 `tabs/weekly/templates/YYYY-MM-DD 주간 보고.md`. 대시보드의 템플릿 내려받기와 같은 파일이다. 매번 이 파일을 읽고 섹션 이름·순서·적는 법을 그대로 따른다. 이 문서에 섹션 목록을 따로 외워 두지 않는다.
- **섹션별 쓰는 법**: 대시보드 주간 보고 뷰어의 `표준 섹션 안내` 창과 같다.

## 절차

### 1. 기간과 저장 폴더 정하기

- 금주는 오늘이 속한 주의 월요일~금요일, 차주는 다음 주 월요일~금요일이다. 사용자가 기간을 주면 그 값을 쓴다.
- 저장 폴더는 `~/.config/dobbys-dashboard/config.json`의 `tabs.weekly.folders` 첫 항목이다. 파일이 없거나 값이 없으면 사용자에게 묻는다. 대시보드 설정 파일은 읽기만 한다.
- 파일명은 `{금주 월요일} 주간 보고.md`(예: `2026-11-09 주간 보고.md`)다. 같은 이름 파일이 이미 있으면 덮어쓰지 말고 사용자에게 묻는다.

### 2. 자료 모으기

- **커밋**: 작성자는 `git config user.email`이다. 저장소는 사용자가 지정한 경로, 없으면 현재 폴더가 git 저장소일 때 그 저장소를 쓰고, 둘 다 아니면 묻는다. 저장소마다 아래를 실행한다. 읽기만 한다.

  ```bash
  git -C <저장소> log --since="<금주 월요일> 00:00" --until="<오늘> 23:59" \
    --author="<이메일>" --no-merges --date=short --format="%ad %h %s"
  ```

- **Jira**: 커밋 메시지의 이슈 키(`[A-Z][A-Z0-9]+-[0-9]+`)를 모은다. 이슈 제목·상태·기간은 사용자가 붙여 넣은 목록이나 이 세션에서 쓸 수 있는 Jira 도구로 확인한다. 확인할 수 없는 값은 지어내지 않는다.

### 3. 확인받기 (필수)

초안을 쓰기 전에 아래를 보여 주고 확인받는다. 확인 없이 파일을 쓰지 않는다.

- 업무 묶음: 이슈 키별 커밋, 이슈 키가 없는 커밋은 기능·목적별로 묶은 작업 단위
- 이번 주 핵심 업무 순서(1·2번이 대시보드 회차 목록의 제목·부제가 된다)
- 진행률·차주 계획처럼 자료로 알 수 없는 값

### 4. 초안 쓰기

- 템플릿의 `#` 제목과 `##`·`###` 섹션 이름을 바꾸지 않는다. 쓸 내용이 없는 섹션은 지우지 말고 `- 없음`으로 둔다.
- `이번 주 핵심 업무` N번과 `업무별 상세 내용`의 `### N.` 카드는 같은 업무, 같은 순서다.
- `업무별 상세 내용`의 각 업무에는 `수행 내용:` `확인 결과:` `의사결정/원인:` `다음 단계:` 네 줄을 모두 두고, 내용은 그 아래 불릿으로 쓴다.
- 자료로 확인하지 못한 사실은 쓰지 않고 그 자리에 `확인 필요`를 남긴다. 대시보드가 미해결 항목으로 모은다.
- `PPT 붙여넣기용`은 PPT에 그대로 붙일 줄 단위 글이다. Markdown 불릿을 붙이지 않는다.
- `출처 및 검증`에는 실제로 읽은 저장소·커밋 범위·Jira 출처를 적는다.
- `PPT 처리`는 `미처리`로 둔다.

### 5. 저장과 안내

- 1단계 폴더에 파일 하나만 쓴다. git add·commit·push, Jira 수정, PPT 수정은 하지 않는다.
- 저장한 경로와 초안 전문을 보여 주고, 대시보드 주간 보고 탭에서 `최신화`를 누르면 회차가 보인다고 안내한다.
